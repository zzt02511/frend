# 登录、密码直播间与 PostgreSQL 收口设计

## 目标

将现有已能人工使用的后台登录、直播间访问密码和 PostgreSQL 功能收口为可测试、可迁移、可重复部署的实现。生产环境以 PostgreSQL 为唯一数据源；微信公众号授权保持现状，不在本次范围内改造。

## 范围

本次包含：

- 后台页面和管理 API 的服务端认证与角色授权。
- 新建、修改、查看和清除直播间访问密码。
- 观众验证密码后获得房间级访问凭证。
- 房间访问凭证覆盖播放 Token、评论、点赞、连麦等受保护操作。
- PostgreSQL 增量持久化、正式 Prisma Migration 和一次性 JSON 数据导入。
- Docker 环境变量、自动化测试、构建和本地数据库冒烟验证。

本次不包含：

- 微信公众号 OAuth 流程调整。
- 腾讯云 CDN 推流链路调整。
- 新的后台页面布局或视觉改版。
- 多租户体系。

## 权限模型

后台账号继续通过 NextAuth Credentials 登录。账号密码使用现有 scrypt 单向哈希，不提供原密码查看。

直播间管理权限如下：

- `super_admin`、`director`、`moderator`：创建、修改和删除非直播中的房间，并查看、设置或清除房间访问密码。
- `host`：开播、关播及主播职责范围内的连麦操作，不能创建或修改房间配置。
- `audience`：只能使用观众侧公开能力。

Middleware 只负责快速跳转或返回 401。每个管理 API 必须调用服务端 `requireAuth()` 并校验角色，不能仅凭 Cookie 名称、客户端 `actorId` 或客户端提交的角色做授权。

## 直播间访问密码

### 存储

访问密码需要允许后台授权人员回看，因此使用 AES-256-GCM 可逆加密，不使用单向哈希。数据库保存密文、随机 IV 和认证标签组成的版本化字符串，不保存明文。

加解密使用独立环境变量 `ROOM_PASSWORD_ENCRYPTION_KEY`。密钥必须解码为 32 字节。生产环境配置了带密码房间却缺少有效密钥时，相关创建、读取和验证操作必须明确失败，不能退回明文。

公开直播详情和列表永不返回密码或密文。授权后台获取单个房间的管理详情时，服务端解密并返回访问密码。设置密码、保持原密码和清除密码使用不同语义，避免编辑标题时意外清空密码。

### 房间访问凭证

观众提交正确密码后，服务端签发短期房间访问凭证并写入 HttpOnly、Secure、SameSite=Lax Cookie。凭证至少包含直播 ID、观众 ID、签发时间和过期时间，并使用服务端密钥签名。

凭证只对对应直播间有效，不能跨房间复用。无密码房间无需房间凭证。密码变更或清除时通过密码版本号使旧凭证失效。

以下观众操作在带密码房间中必须验证房间访问凭证：

- 获取 LiveKit 播放或连麦 Token。
- 进入直播间和发送心跳。
- 发表评论、点赞和观众事件。
- 申请、结束观众连麦。

前端遮罩只是交互体验，服务端凭证才是安全边界。分享链接不包含明文密码。

## PostgreSQL 架构

生产环境以 Prisma/PostgreSQL 为唯一事实来源。JSON Repository 只允许在明确的本地开发模式下使用，不作为生产故障自动降级，避免数据库异常时产生分叉数据。

现有“加载整库到全局内存、保存时删除所有表再重建”的方式将被移除。业务写操作改为通过 PostgreSQL Repository 做针对记录的增量创建、更新和删除；需要同时更新统计或审计的操作使用 Prisma 事务。

Repository 接口改为异步，并由 API、页面和 Service 显式等待。全局内存对象不再作为生产数据源。JSON 实现保留相同接口，供测试和本地演示使用。

创建正式 Prisma Migration，覆盖当前 schema 相对初始迁移缺失的字段，包括用户密码哈希、直播 CDN 地址、加密访问密码及密码版本。重新生成 Prisma Client，删除 `@ts-nocheck`。

提供一次性 JSON 导入命令：

- 导入前验证目标数据库核心表为空。
- 在单个事务内导入用户、直播、参与者、评论、连麦、回放、统计、审计、分享访问和客户跟进。
- 已有数据时拒绝执行，除非未来另行设计显式覆盖方案。
- 输出导入数量，不输出账号密码、房间密码或密钥。

## 数据流

后台创建房间时，API 首先验证 Session 和角色，然后校验输入、加密访问密码，并在事务中创建直播和统计记录。后台读取管理详情时才解密密码；公开读取使用独立的公开 DTO。

观众进入带密码房间时，先调用密码验证端点。服务端读取密文、解密比较，成功后签发房间 Cookie。后续 Token 和互动接口从 Cookie 中验证直播 ID、观众 ID、密码版本和有效期。

数据库不可用时，生产请求返回明确的服务错误并保留日志，不切换到 JSON。开发环境只有在显式选择 JSON Repository 时才读取 `.data/app-store.json`。

## 错误处理

统一使用稳定错误码：

- `AUTH_REQUIRED`
- `AUTH_INSUFFICIENT_ROLE`
- `ACCESS_PASSWORD_REQUIRED`
- `ACCESS_PASSWORD_INCORRECT`
- `ROOM_ACCESS_REQUIRED`
- `ROOM_ACCESS_EXPIRED`
- `ROOM_PASSWORD_KEY_INVALID`
- `DATABASE_UNAVAILABLE`
- `IMPORT_TARGET_NOT_EMPTY`

日志不得包含登录密码、直播间明文密码、加密密钥、完整 Session Token 或房间访问凭证。

## 测试与验收

自动化测试覆盖：

- 未登录请求不能创建、修改或删除直播。
- `super_admin`、`director`、`moderator` 可以创建和修改直播。
- `host` 和 `audience` 不能创建或修改直播。
- 管理详情可向授权角色返回解密后的访问密码，公开接口不泄露密码或密文。
- 设置、保持和清除密码语义互不混淆。
- 错误密码不能获得房间凭证，正确密码可以。
- 伪造、过期、跨房间以及旧密码版本凭证均被拒绝。
- 带密码房间的 Token、评论、点赞、心跳和连麦接口拒绝无凭证访问。
- 无密码房间保持原有观众流程。
- PostgreSQL 增量写入不会删除无关记录。
- JSON 导入在空库成功，在非空库拒绝。

最终质量门禁：

- `npm run test`
- `npm run lint`
- `npm run build`
- `npm run prisma:validate`
- Prisma Migration 在空数据库和已有初始迁移的数据库上验证成功。
- 本地 PostgreSQL 冒烟验证登录、创建带密码房间、观众验证、互动、重启后数据仍存在。

## 部署与回滚

部署前备份 PostgreSQL 和现有 JSON 数据。先部署 Migration，再部署应用和环境变量。必须配置强随机 `AUTH_SECRET` 与独立的 `ROOM_PASSWORD_ENCRYPTION_KEY`。

首次切换通过一次性导入命令迁移 JSON 数据，核对核心表数量后再启用 PostgreSQL-only 应用。回滚采用数据库备份和上一版本镜像，不通过运行时自动退回 JSON。

部署完成后更新 `AGENTS.md`，记录测试数量、Migration、导入结果、生产环境变量是否存在（只记录已设置，不记录值）、容器健康状态和公开页面/API 冒烟结果。

# SaaS 租户与账号管理开发说明

## 目标

系统采用 SaaS 多租户模式。平台方使用总管理员账号维护客户管理员；每一个客户管理员对应一个独立租户。租户之间的账号、直播间、主播、录播、观众互动及运营数据必须严格隔离。

## 账号层级

| 角色 | 账号归属 | 主要权限 |
| --- | --- | --- |
| `super_admin` | 平台方 | 查看全部租户；创建、修改、禁用客户管理员；设置账号期限；维护平台配置。 |
| `director` | 一个租户 | 租户管理员；创建、修改、禁用本租户的主播和场控；维护本租户直播间、录播和运营数据。 |
| `moderator` | 一个租户 | 仅处理本租户直播的审核、观众和连麦事务。 |
| `host` | 一个租户 | 仅进入被分配的主播端直播间，开播、结束直播及处理连麦。 |
| `audience` | 观众 | 仅访问获授权的直播间，无后台管理权限。 |

`director` 是客户管理员，不是全平台管理员。只有 `super_admin` 可以跨租户查看和维护账号。

## 账号管理规则

### 总管理员

- 在 `/admin/users` 查看所有客户管理员及其账号状态。
- 可新增、改名、重置密码、启用/禁用、设置到期日。
- 可创建 `director` 账号并为其创建/分配租户。
- 不应将一个 `director` 直接归属到另一位 `director`。

### 客户管理员

- 在租户账号管理入口仅查看本租户员工。
- 可新增与维护 `host`、`moderator`。
- 不可新增 `super_admin`，不可维护其他租户的 `director`、主播或场控。
- 员工账号到期、被禁用或改租户后，下一次登录必须失效。

### 账号期限

- `createdAt`：创建日期，只读显示。
- `expiresAt`：使用截止日期；为空表示永久有效。
- 账号状态不是 `active` 或当前时间超过 `expiresAt` 时，密码登录必须拒绝。
- 到期账号不删除历史数据；总管理员续期后可恢复登录。

## 数据模型（待完成的多租户迁移）

现有 `User` 已有 `role`、`status`、`passwordHash`、`createdAt`、`expiresAt`。正式 SaaS 隔离需新增以下结构：

```text
Tenant
  id
  name
  status
  expiresAt
  createdAt

User
  tenantId?          // super_admin 为空；director/host/moderator 必填
  role
  status
  expiresAt

LiveSession
  tenantId           // 必填
```

依赖 `LiveSession` 的评论、连麦、参与者、统计、录播、分享访问和客户跟进记录可通过 `liveId` 继承租户边界；查询时必须先用 `tenantId` 限制直播间集合，不能只依赖前端筛选。

## 服务端权限要求

1. 每个管理 API 都调用 `requireAuth()`，不能信任客户端提交的 `userId`、`role` 或 `tenantId`。
2. `super_admin` 可跨租户查询。
3. `director`、`moderator`、`host` 的目标直播间必须满足 `live.tenantId === currentUser.tenantId`。
4. `director` 创建账号时，服务端强制使用当前管理员的 `tenantId`，忽略请求体中的租户字段。
5. `host` 仅能操作 `hostUserId === currentUser.id` 的直播间。
6. 观众接口不返回后台账号、密码哈希、租户内部数据或跨租户统计。

## 迁移方案

1. 创建 `Tenant` 表；创建“默认租户”。
2. 将现有 `director-1`、`host-1`、`moderator-1` 与现有直播间归入默认租户。
3. `admin-1` 保持为 `super_admin`，其 `tenantId` 为空。
4. 为 `User.tenantId`、`LiveSession.tenantId` 添加索引；数据回填完成后，将员工和直播间的租户字段设为必填。
5. 所有管理查询改为服务端按租户过滤；补充跨租户访问拒绝测试。
6. 将 `/admin/users` 拆分为：平台账号管理（总管理员）与租户员工管理（客户管理员）。

迁移必须先备份 PostgreSQL，并在演练数据上验证：旧直播、旧录播、旧分享链接及主播端都仍可正常使用。

## 验收标准

- 总管理员能创建一个客户管理员并设置期限。
- 客户管理员只能看到本租户的主播、场控和直播间。
- 客户管理员能新增、重置密码、禁用本租户主播。
- 客户管理员不能读取或修改其他租户账号、直播间、录播和线索。
- 主播无法进入其他租户直播间。
- 到期或禁用账号无法登录；续期后可正常登录。
- 平台总管理员可查看全部租户与全部直播数据。

## 实施完成记录（2026-08-11）

- `User.tenantId` 和 `LiveSession.tenantId` 已迁移到 PostgreSQL；历史员工和直播间归入 `default-tenant`，超级管理员不归属任何客户。
- 当前版本采用“客户管理员即租户入口”的轻量模型：创建 `director` 时系统生成 `tenant-<账号ID>`；其旗下主播、场控和直播间均由服务端写入相同的租户标识。
- `/admin/users` 已按登录身份提供平台账号管理和客户旗下账号管理。平台可维护客户管理员和全部员工；客户管理员只能维护本客户的 `host`、`moderator`，可启用、禁用、重置口令和设置使用期限。
- 登录页为 `/login`。账号禁用或到期后，密码登录和已有后台会话都会被服务端拒绝。
- 后台房间页、主播房间页，以及创建、编辑、删除、开播、结束、管理详情和主播令牌等敏感操作均执行租户边界校验；`super_admin` 保留查看全部客户的权限。

### 运维使用说明

1. 超级管理员登录 `/admin` 后进入“账号管理”，先创建客户管理员账号（角色 `director`）。
2. 客户管理员登录后，通过同一入口新建自己的主播或场控账号。
3. 使用期限留空表示永久有效；禁用或到期后无法登录，续期后恢复。
4. 创建直播时会自动选用当前客户的可用主播；没有主播账号时先在账号管理中新建主播。
